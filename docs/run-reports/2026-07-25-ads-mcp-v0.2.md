# ads-mcp v0.2 visual judgment and SwiftUI adapters

## Outcome

Implemented the next local stdio MCP slice without changing the public three-tool sequence:

1. `ads_evaluate` now supports an explicit `judge.mode: "configured"` path. A startup-configured
   command adapter receives the rubric, deterministic gates, optional comparison, and screenshot
   evidence, then returns a typed verdict, scores, findings, and revision prompt.
2. `ads_render` now accepts a root-confined SwiftUI target. A startup-configured command adapter
   writes snapshot PNGs and `evidence.json` into the caller-owned run directory.
3. The default model-free behavior is preserved. `judge.mode: "none"` still returns
   `needs_human`, and missing or invalid adapters preserve blocked evidence instead of returning a
   false pass.

The package and MCP server metadata are aligned at `ads-mcp@0.2.0`. The release path advances the
public `/mcp` page, npm package, and Registry entry together so the visible contract and installable
implementation cannot disagree.

## Visual-judgment contract

- Provider and model are fixed at server startup and copied into immutable evaluation receipts.
- A model call requires dual opt-in: startup adapter configuration and
  `judge.mode: "configured"` on the evaluation.
- The command protocol uses one bounded JSON request and response over stdin/stdout with fixed
  argv execution and no shell.
- The server validates exact rubric score keys, scores from 0 through 10, ADS finding categories,
  severity, rubric rows, screenshot references, matching state and breakpoint metadata, normalized
  regions, verdict consistency, and the presence of a revision prompt for non-satisfied verdicts.
- Missing, timed-out, malformed, or semantically inconsistent adapter output returns `blocked`.
- Any render or comparison blocker prevents automated judgment.

## SwiftUI contract

- SwiftUI targets identify a root-confined Xcode project or workspace, scheme, optional source
  file, configuration, and device.
- The external renderer receives canonical absolute paths plus requested states, viewports, output
  directory, and timeout.
- Every requested state and viewport pair must have one safe root-level PNG recorded in
  `evidence.json`.
- Adapter availability, build success, and state distinctness are hard gates.
- Declared SwiftLint, SwiftSyntax, asset-catalog, and 44pt touch-target detectors become hard
  availability and failure gates.
- Run manifests record `platform`, `renderer`, `detectors`, and the optional Swift source hash.

The core package deliberately does not bundle a universal Xcode snapshot harness. Teams may use
Xcode Previews, snapshot tests, or a simulator runner behind the same command contract.

## Security boundary

- Adapter executables must be canonical absolute executable files.
- Adapter processes receive fixed arguments, never a shell command string.
- stdout is capped at 1 MiB, cancellation kills the subprocess, and stderr is not copied into MCP
  receipts.
- Project paths remain confined to `--root`, including symlink resolution.
- Screenshot and finding evidence must resolve to artifacts supplied by the current run.

## Failed checks and open risks

- The first repository release-gate attempt stopped because the clean worktree lacked root
  dependencies. After `npm ci --ignore-scripts`, it advanced and exposed the missing demo
  dependencies. After `npm ci --prefix demos --ignore-scripts`, it advanced and exposed the missing
  Playwright Chromium runtime. Installing the documented browser prerequisite made the full gate
  pass. These were clean-worktree prerequisites, not source failures.
- `npm audit --omit=dev` for `packages/ads-mcp` still reports two moderate advisories through
  `@modelcontextprotocol/sdk` and `@hono/node-server`. The affected Hono static-serving path is not
  used by this local stdio server. The offered automatic fix downgrades the SDK and should not be
  applied without compatibility evidence.
- Installing the existing demo dependency lock reported 10 advisories, including one critical.
  They are outside the MCP runtime and were not introduced by this slice, but remain repository
  dependency debt.
- Aaron approved the npm publication, Registry update, and public `/mcp` release on 2026-07-25.
- The first v0.2 page-runtime run used a broad `header` locator after adding a version assertion;
  Playwright correctly rejected the ambiguous match. The assertion now targets the page header,
  uses `textContent` so the intentionally hidden mobile status remains testable, and passes all
  three viewports.
- The first Registry validation rejected the server description at 105 characters against its
  100-character limit. The package and Registry descriptions were tightened to the same accurate
  90-character summary before publication; the manifest then validated.
- The source-only page heuristics still warn about loading, empty, error, responsive, and
  focus-visible signals because this is a static server-rendered article and the checks cannot see
  its CSS module or shared focus-ring utility. The route has no remote data states. Authoritative
  rendered evidence cleared the corresponding responsive, focus/touch, semantic, and accessibility
  gates.
