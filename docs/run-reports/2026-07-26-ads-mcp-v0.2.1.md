# ads-mcp v0.2.1 cold-start repair

## Outcome

Repaired the published-package startup path that prevented a cold Claude Code consumer from seeing
any tools inside its 30-second MCP connection budget.

The server no longer downloads Chromium during package installation. A cold `npm exec` launch from
an isolated npm cache now connects in 2,332 ms, exposes exactly `ads_render`, `ads_evaluate`, and
`ads_trace`, and does not download a browser. Chromium provisioning is explicit:

```bash
npx --yes ads-mcp@0.2.1 setup
npx --yes ads-mcp@0.2.1 doctor
```

If an agent calls `ads_render` before setup, the server preserves a blocked run with evidence and
returns the exact setup and doctor commands. It does not hang, silently omit tools, or fabricate a
successful render.

## Task specification

- Goal: make a cold published-package MCP handshake complete inside Claude Code's 30-second budget.
- Why: the v0.2.0 postinstall downloaded a large browser dependency before the server could answer
  MCP initialization, so a cold client timed out and saw zero tools.
- Surface: the `ads-mcp` package, its capture runner, release gates, package documentation, and the
  public `/mcp` contract page.
- Constraints: retain exactly three tools, preserve model-free defaults and evidence-integrity
  behavior, never download a browser during server startup, and keep missing prerequisites honest.
- Simplest acceptance check: start the packed package through `npm exec` with an empty npm cache and
  browser directory, list exactly three tools inside 30 seconds, and receive an actionable blocked
  render without a browser download.

## Implementation

- Replaced the browser-downloading `playwright-chromium` alias and package `postinstall` with
  `playwright-core`.
- Added explicit `setup` and `doctor [--json]` commands.
- Added an early browser-readiness check to the default capture path so missing Chromium becomes a
  preserved blocked run.
- Added a packed cold-start regression using an isolated npm cache, an empty browser directory, and
  the same 30-second connection budget as the failed Claude Code session.
- Made rendered run resources discoverable through `resources/list` and emitted resource-list
  change notifications after each tool stage.
- Documented that URL states are transported as `#state=<name>` and added per-field MCP schema
  descriptions.
- Documented the logical `ads://` screenshot URI versus its `evidence/` disk location.
- Advanced package, server, Registry metadata, tests, and the public contract page to v0.2.1.

## Failed checks and open risks

- The first package-smoke rerun failed because its help-text assertion expected the old one-line
  usage format. The assertion now checks the documented server, setup, and doctor commands.
- The first demo build attempt found that the isolated worktree lacked demo dependencies. After the
  lockfile-backed `npm ci --prefix demos`, the production build passed.
- The first page-runtime rerun caught two remaining visible `v0.2` labels. Both now read `v0.2.1`,
  and the desktop, tablet, and iPhone-sized runtime checks pass.
- `npm audit --omit=dev` reports two moderate advisories through the MCP SDK's unused Hono HTTP
  serving path. The local server uses stdio. The automatic fix requires an SDK downgrade and was not
  applied.
- Installing the existing demo lockfile reports 10 advisories, including one critical. They are
  pre-existing demo dependency debt and are outside the local MCP runtime.
